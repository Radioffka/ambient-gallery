## Source provenance

This repository was reconstructed from the earlier `UX Demonstration` workspace used for the Google Photos Ambient API partner-review prototype. The archive intentionally excluded `node_modules` and generated review media such as screenshots/videos.

There was no `.git` directory or GitHub remote in the recovered workspace, so prior commit history is unavailable. This repository is the canonical source history from this baseline forward.

## First Android TV MVP implementation (2026-09-23)

**Code/build result: the real flow is implemented and `:app:assembleDebug` passes locally. On-device end-to-end behavior remains unverified.** The baseline inspection sections above describe the state before this change.

- `MainActivity` now selects `GoogleAmbientPhotosRepository` by default. The mock flow is available only with the explicit Gradle flag `-PambientDemoMode=true`. The reviewer jump bar and simulated authorization/selection actions are absent from the real flow.
- The app requests a device code for the documented Ambient scope, shows Google's verification URL and user code as text plus an encoded QR, polls the token endpoint at Google's returned interval, handles `authorization_pending` and `slow_down`, and creates one Ambient device with a fresh UUID request ID. The signed-in Google account is chosen on Google's consent page, allowing a different consenting account to test the same APK.
- The device's actual `settingsUri` is shown as a QR. The TV polls `devices.get` using `pollingConfig.pollInterval`, waits for `mediaSourcesSet`, and retries an empty default `mediaItems.list` response with bounded backoff. Default listing is used because the earlier direct `mediaSourceId` probes returned HTTP 200 `{}`. Results are paginated, bounded to three 100-item pages per refresh, and refreshed during playback before base URLs expire.
- Photos are displayed fullscreen with Coil, their full aspect ratio, a sized Google base URL, and an authorization header. If Ambient returns a `video/*` MIME type, the app attempts `baseUrl=dv` with Media3; a video playback error advances the queue. Actual Ambient video metadata and `=dv` access remain unverified, so video is not a condition for photo playback.
- TV Back navigation returns from the slideshow to Settings and can cancel an unfinished source setup through device deletion. A video playback failure removes that item from the current queue; when no playable items remain, source polling resumes.
- Access/refresh tokens and device association are stored in app-private preferences encrypted with an Android Keystore AES-GCM key; Android backup is disabled. Disconnect calls `devices.delete`, attempts OAuth revocation, and clears local state. Token refresh is implemented. The app does not display the Google account's email/name.
- OAuth client values are supplied from ignored `ambient-oauth.properties` or `AMBIENT_CLIENT_ID`/`AMBIENT_CLIENT_SECRET` at build time. `scripts/build-tv.ps1` accepts a TV-client JSON outside Git. The configured debug APK contains the client values and must remain private. No credential, token, generated APK, or personal media has been added to Git.
- Local build used Microsoft OpenJDK 17, Android SDK 34, and `./gradlew.bat :app:assembleDebug`; it returned **BUILD SUCCESSFUL** after the final navigation/image changes. The output is `app/build/outputs/apk/debug/app-debug.apk`. This particular APK was built **without OAuth values** because the previous test JSON had been removed and the current Cloud secret value is masked. It can only show the missing-credential setup message; it is not yet a usable live-test APK. The credential build script has not been exercised with a real JSON.
- GitHub Actions Android CI run `35913415619` on the final MVP code completed successfully, including Gradle wrapper validation and the debug APK build. CI also builds without OAuth values.
